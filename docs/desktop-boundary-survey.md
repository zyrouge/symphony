# Desktop Boundary Survey

Purpose: inventory of `:app` code, classified by how it can reach Compose Desktop (JVM) via the KMP `:core` module. Serves decision D1 (first sinking increment) for the dual Android/desktop goal.
Date: 2026-11-18
Scope: `app/src/main/java/io/github/zyrouge/symphony/services/` (47 files), `utils/` (7), root `Symphony.kt`, `MainActivity.kt`, `ActivityIgnition.kt`, `ErrorActivity.kt`; light scan of `ui/` (109 files). Existing `:core` (8 commonMain + 5 jvmSharedMain files) and `docs/audio-metadata-invariants.md` are cited, not re-surveyed.

Classification legend:

- `sinkable-pure`: no Android dependency; moves to `:core` (commonMain/jvmSharedMain) as-is.
- `sinkable-with-abstraction`: mostly pure; named Android types/imports block the move; one-line abstraction given.
- `platform-bound`: intrinsically Android; desktop needs a replacement or counterpart.
- `out-of-scope`: app-lifecycle glue desktop replaces wholesale.

## 3. D1 blockers (numbered)

1. `services/groove/AudioMetadataSource.kt:109` — `AudioMetadataSource.read(context: Context, file: DocumentFileX)`: both parameter types are Android. The contract data types (`RawAudioMetadata`, `CoverPlan`, `SongFields`, `EmbeddedPicture`, `ArtworkPolicy`, `FileInfo`, `ResolutionOptions`, `SongResolution`) use only `java.time.LocalDate`, `Regex`, and stdlib — verified pure.
2. `services/groove/AudioMetadataSource.kt:163-188` — `MetaphonyMetadataSource` calls `context.contentResolver.openFileDescriptor(file.uri, "r")` and the fd-based `AudioMetadataParser.parse` from `:metaphony` (Android JNI/TagLib). Desktop needs a jaudiotagger source behind the same interface; the interface must offer a path/stream-based read channel, not only fds.
3. `services/groove/AudioMetadataSource.kt:190-247` — `MediaMetadataRetrieverSource` is hard-bound to `android.media.MediaMetadataRetriever` and `Build.VERSION.SDK_INT >= S`; stays Android-only, so the source list must be per-platform.
4. `services/groove/AudioMetadataSource.kt:buildSongFields` → `services/groove/Song.kt:229-246` — the resolver calls `Song.parseMultiValue`, pulling the Room `@Entity` Song (with `android.net.Uri` field, `android.graphics.Bitmap` artwork code at `Song.kt:163-194`) into the pure resolver chain.
5. `services/groove/Song.kt:174-194` — `applyCoverPlan` executes CoverPlan with `BitmapFactory.decodeByteArray` + `Bitmap.compress(JPEG)` + `ImagePreserver.resize`; the resolver can sink only if cover execution is an injected `ArtworkSink` (bytes in, stored name out).
6. `utils/DocumentFileX.kt` — SAF/DocumentsContract file node consumed by both `MediaExposer` and `AudioMetadataSource.read`; no JVM equivalent exists, so sinking the scanner/resolver requires an `AudioFile`/`FileNode` abstraction with a `java.nio.file.Path` desktop impl.
7. `utils/Logger.kt:3` — `android.util.Log`; used by Song.parse, Radio, repositories. Blocks sinking any file that logs. Trivial expect/actual.
8. `services/Settings.kt:288-296` — `mediaFolders: Set<Uri>` (Android Uri) plus SharedPreferences backing; scanner inputs and persisted settings are Android-typed. Also couples Settings to ui enums (ThemeMode, HomePage, etc.).
9. `Symphony.kt` — every service/repository/entity takes `symphony: Symphony`; nothing sinks without constructor-level decoupling from this god-object.
10. `services/groove/Song.kt:20-48`, `services/groove/Playlist.kt:13-21` + `services/database/store/{SongCacheStore,PlaylistStore}.kt` + `utils/RoomConvertors.kt` — Room entities with `android.net.Uri` fields and Android DAOs; persistence is non-portable until entities carry `uri: String` and DAOs are re-declared per platform.
11. `services/groove/repositories/{Song,Album,Artist,AlbumArtist}Repository.kt` — import `ui.helpers.Assets`/`createHandyImageRequest` (Coil, `R.raw` placeholders): services layer depends on UI/resources for artwork requests.
12. `services/i18n/Translations.kt:9` + `i18n/Translator.kt:26-29` — `assets.open(...)` and `LocaleListCompat.getDefault()` block sinking i18n; need a resource-stream loader and `java.util.Locale`.

## 4. Suggested D1 task breakdown (ordered)

1. **Foundations in :core** — add expect/actual `Logger` (Android `Log` / JVM stderr); move `utils/Fuzzy.kt`, `utils/Http.kt`, `database/adapters/FileDatabaseAdapter.kt`, `FileTreeDatabaseAdapter.kt` to `:core` jvmSharedMain. Verify: app builds; existing 76 host tests (`app/src/test/...`) stay green.
2. **Sink the metadata contract + resolver** — move the pure half of `services/groove/AudioMetadataSource.kt` (all data types + `readFirstAvailable`, `buildSongFields`, `coverPlanFor` + helpers) to `:core`; move `Song.parseMultiValue`/`makeSeparatorsRegex` out of the Song companion into core; redefine `AudioMetadataSource.read(file: AudioFile)` with an `AudioFile` interface; keep `MetaphonyMetadataSource`/`MediaMetadataRetrieverSource` in `:app` implementing it via `DocumentFileX`. Verify: `AudioMetadataContractTest` + `AudioMetadataResolutionTest` + `SongTest` relocated to `core/jvmTest`, all green (pins `docs/audio-metadata-invariants.md` INV-1..11).
3. **Artwork execution abstraction** — introduce `ArtworkSink` (name + bytes → stored name); Android impl keeps `BitmapFactory`/`ImagePreserver`; move `ImagePreserver.Quality` + dimension math to core. Verify: resolution tests covering `coverPlanFor` stay green; manual Android scan smoke check.
4. **Desktop file provider + jaudiotagger source** — `java.nio.file.Path` impl of `AudioFile`/file-tree; JVM `AudioMetadataSource` via jaudiotagger in the desktop module. Verify: new host test scanning a temp-dir fixture through `readFirstAvailable`/`buildSongFields`.
5. **Sink queue logic** — move `radio/RadioEffects.kt`, `RadioQueue` (+ `Serialized`), `RadioPlayer.PlaybackPosition`, speed/pitch constants to core; put `Radio`, `RadioShorty`, `RadioObservatory` behind a `Player`/`PlayerFactory` interface. Verify: new host tests for `Serialized.parse/serialize` round-trip and queue add/remove/shuffle invariants; Android app behavior unchanged.
6. **Sink repository aggregates** — extract pure cache/search/sort/`onSong` aggregation from the 6 repositories into core classes taking a settings snapshot (separator regexes, case-sensitivity); move `Assets`/`createHandyImageRequest` artwork fns up to the app/UI layer. Verify: new host tests asserting sort/search parity with current behavior; 76 existing tests green.

## 5. Confidence notes

- `ActivityIgnition.kt` — classified out-of-scope; its only dependency is `androidx.lifecycle.ViewModel`, so it could equally be called sinkable-with-abstraction, but desktop would rewrite app ignition anyway.
- `services/database/Database.kt` — classified platform-bound (it eagerly constructs Room databases); it is thin wiring that desktop replaces rather than ports.
- `services/radio/Radio.kt` — classified sinkable-with-abstraction on the strength of zero android imports, but it directly news-up `RadioPlayer`/`RadioSession`/`RadioFocus`/`RadioNativeReceiver`, so the abstraction work is real (Player factory + effect callbacks), not mechanical.
- `utils/Fuzzy.kt` — sinkable-pure for jvmSharedMain (fuzzywuzzy is pure Java); it cannot go to commonMain without a Kotlin reimplementation.
